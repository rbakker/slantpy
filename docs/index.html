slantpy

SLANT whole-brain segmentation without Matlab. A T1-weighted MRI goes in, 132 BrainCOLOR regions come out, on the original image grid.

2 / 5.9 Mvoxels differ from the original pipeline in MNI space
~2 GBmemory on CPU, where the original asks for up to 50 GB
2.7 minper scan on a GPU; the docker image took 24 min on CPU

Figures from one test scan on one workstation. slantpy is a Python port of SLANT (Huo et al., NeuroImage 2019) and uses its trained networks.

How it works

RegisterT1 to the MNI305 template, affine (NiftyReg)
CorrectN4 bias field (ANTs), then intensity normalisation
Segment27 overlapping tiles, one 3-D U-Net each
Fusemajority vote where tiles overlap
Resamplelabels to the original grid with the inverse affine

Dashed steps call an external program; the rest is Python.

The 27 tiles

The MNI volume is 172 × 220 × 156 voxels. Each network sees one block of 96 × 128 × 88 voxels at a fixed position, three positions per axis. Pick a tile to see where it sits.

x y z

Voxels in the middle of the brain are covered by all 27 tiles, voxels in the corners by one. The final label is the one most tiles voted for.

What you need

  • Python 3.9 or newer with numpy, scipy, nibabel and PyTorch. matplotlib for the QA page; h5py only for a v7.3 atlas_model.mat.
  • The SLANT model files: 27 network weight files, atlas_model.mat and the MNI305 template. They are not in the repository. slantpy extract copies them out of the SLANT docker image (see Install).
  • reg_aladin and N4BiasFieldCorrection: from the docker image, or from the conda packages niftyreg and ants.

Install

pip install git+https://github.com/rbakker/slantpy.git

Get the model files

The trained networks are distributed by the SLANT authors inside their docker image, as described in the SLANT README. Pull it once and let slantpy copy out what it needs:

docker pull masidocker/public:deep_brain_seg_v1_1_0_CPU
slantpy extract masidocker/public:deep_brain_seg_v1_1_0_CPU /data/resources/SLANT

The GPU build masidocker/public:deep_brain_seg_v1_1_0 works as well; the model files are the same. After this step docker is no longer needed, unless you choose to run the registration tools inside the image. extract creates this folder, which every later command takes as --extra-dir:

/data/resources/SLANT/
    model_dir/<tile>/finetune_out/models/model_epoch_0027.pth    27 tiles
    full-multi-atlas/MNI/average305_t1_tal_lin*.nii.gz
    full-multi-atlas/atlas-processing/atlas_model.npz
    full-multi-atlas/niftyreg/   full-multi-atlas/ANTs-bin/       binaries from the image

Run

slantpy run t1.nii.gz out/ --extra-dir /data/resources/SLANT
OutputContent
out/FinalResult/t1_seg.nii.gzLabels on the original grid, 8-bit.
out/FinalVolTxt/t1_label_volumes.txtVolume of each region in mm³.
out/FinalPDF/t1_result.pdfOne-page QA view.
out/t1/Intermediate files. A rerun resumes from them.

The input file is never modified. Only the subject's output folder is written to, or mounted into a container.

Options

OptionMeaning
--device cpu / cuda:1Default: the GPU with the most free memory if it has enough, otherwise the CPU. A GPU that runs out of memory part-way hands over to the CPU.
--threads NCPU threads for PyTorch.
--interpLabel interpolation to native space: linear (default), nearest or gaussian.
--postproc legacy
--forward literal		Behave like the original pipeline.
--tools-docker-imageRun reg_aladin and N4 inside the docker image instead of on the host.
--halfMixed precision on GPU. Not bit-identical.
--no-pdf, --keep-tiles, --piecesSkip the QA page; keep per-tile labels; run single tiles for debugging.

Differences from the original

By default slantpy changes two things. Both can be switched back.

Network evaluation

Same layers and weights. The last three layers contain no normalisation, so they are evaluated in slabs, and the concatenated skip tensors are never built. Peak memory for one tile on CPU drops from 4.2 GB to 1.7 GB with the same run time.

Back to native space

The original registers the MNI-space image back to the T1 a second time, runs an ANTs registration between two label images to convert that transform, and then resamples. slantpy inverts the affine it already has and resamples once, label by label.

Results are not interchangeable. On the test scan the default output and the docker output differed in 7 % of brain voxels. Regional volumes differed by 1.9 % on average and total brain volume by 0.2 %. Do not mix the two within one study.

The worst region improves from a Dice of 0.82 to 0.91. The direct mapping reproduces reg_aladin's own resampled image with a correlation of 0.999, where a one-voxel error would give about 0.97.

This is a single scan, and the round-trip test shares its affine with the default method, so read it as supporting evidence. To repeat it on your own data:

python scripts/compare_with_docker.py t1.nii.gz --workdir /scratch/cmp
python scripts/check_native_mapping.py /scratch/cmp/improved/t1/t1 seg_a.nii.gz seg_b.nii.gz

Conda and Snakemake

workflow/envs/slantpy.yaml is an environment file for the conda: directive and workflow/slant.smk an example rule.

rule slant:
    input:  t1="{sample}/t1.nii.gz"
    output: seg="{sample}/slant/FinalResult/t1_seg.nii.gz"
    params: out="{sample}/slant", extra=config["resources"] + "/SLANT"
    threads: 4
    conda:  "envs/slantpy.yaml"
    shell:  "slantpy run {input.t1} {params.out} --extra-dir {params.extra} "
            "--threads {threads} --no-pdf"

The conda packages niftyreg and ants are current releases, not the 2018 builds in the docker image, so registration and N4 results differ slightly from the image. Binaries found under the resources folder take precedence over those in the environment.

Known quirks kept from the original

  • The networks run in training mode at test time, so batch normalisation uses each tile's own statistics. The weights were validated that way.
  • Each tile is scaled by its own minimum and maximum, so one very bright voxel changes the input of the whole tile.
  • Ties in the majority vote go to the lowest label number.
  • The registration called "rigid" in the original code is a 12-parameter affine.

The design notes explain these and the memory measurements in detail.
